# Design System Skill

## Workflow
1. Review brand assets and current UI before inventing new tokens.
2. Define semantic tokens for color, typography, spacing, radius, borders, shadows, breakpoints and motion.
3. Define reusable patterns for buttons, links, forms, alerts, cards, tables, badges, dialogs and navigation.
4. Specify interaction states and accessible focus treatment.
5. Use semantic variants rather than arbitrary one-off values.
6. Document exceptions and prevent premature component abstraction.

## MQTech requirements
- Public site should feel approachable and technically credible.
- Admin UI should favor scanability, speed, status clarity and dense-but-readable information.
- Status colors must also have text labels and not rely on color alone.
- Forms must have explicit labels, helpful validation and mobile-friendly controls.

## Outputs
- Design token specification.
- Component behavior contract.
- Usage examples and anti-patterns.
- Accessibility notes.

## Do not
- Create a design system before understanding the product.
- Add a component for a single trivial use unless reuse or consistency justifies it.
